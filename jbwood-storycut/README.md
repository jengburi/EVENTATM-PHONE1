# JBWOOD AI StoryCut

목공 공방 촬영본을 넣으면 **음성을 분석해서 편집 초안(MP4 + SRT 자막)** 을 만들어 주는 프로그램입니다.
결과는 캡컷 PC에서 이어서 수정할 수 있습니다.

> 현재 버전: **0.1 (1단계 MVP)** — 음성 인식, 문장 단위 자동 컷, 말버릇·더듬기·다시 말한 문장 제거,
> 예능형 강조 자막, 오프닝 지정, 확인 후 적용(2단계 작업 흐름), GUI

| 확인 후 적용 | ✅ 구현 | 분석 → 표에서 확인/수정 → 적용. 다시 적용할 때 음성 인식 재실행 안 함 |

| 장면 인식(인물·손·공구·제품), B-roll 자동 삽입 | 🔜 3단계 | PySceneDetect + 영상 AI. 정확도는 촬영 방식에 크게 좌우됨 |
| 감정에 따른 자막 크기/스타일 | 🔜 2단계 | AI가 문장 감정 태그를 붙이면 자막 스타일에 반영 |
| 효과음·배경음악 | 🔜 3단계 | **저작권 확인된 음원을 사용자가 폴더에 넣는 방식**. 프로그램이 임의로 음원을 받아오지 않음 |
| 자동 확대(줌) | 🔜 3단계 | 강조 문장에서만 살짝 확대 |
| 캡컷 프로젝트 파일 직접 생성 | ⚠️ 4단계, 실험적 | 아래 참고 |

### 캡컷 연동 조사 결과

- **캡컷 PC는 공식 편집 API가 없습니다.**
- **공식 지원 방법:** 캡컷 PC는 **SRT 자막 가져오기**를 지원합니다(UTF-8 권장). 그래서 이 프로그램은
  *자막 없는 MP4 + SRT* 를 함께 만들어, 캡컷에서 자막 스타일을 고르고 이어서 편집할 수 있게 합니다. → **지금 바로 사용 가능**
- **비공식 방법(프로젝트 파일 직접 생성):** 캡컷 프로젝트는 `draft_content.json` 파일입니다.
  국제판 CapCut은 아직 평문(읽을 수 있음)이라는 보고가 많지만, 중국판(JianYing) 6.0 이상은 암호화됐고,
  캡컷이 업데이트되면 예전 방식으로 만든 프로젝트를 거부한 사례도 있습니다.
  → 4단계에서 **사용자 PC의 실제 캡컷 버전으로 검증**한 뒤, **원본 백업 + 새 프로젝트로만 생성**(기존 프로젝트는 절대 수정 안 함) 방식으로 진행합니다.
- 내 PC의 캡컷 버전과 프로젝트 파일 형식은 `check.bat` 으로 확인할 수 있습니다(읽기만 함).

## 2. 설치 (윈도우)

1. 이 `jbwood-storycut` 폴더를 PC에 복사합니다.
2. **`install.bat` 더블클릭** — 파이썬, FFmpeg, 필요한 패키지를 설치합니다.
   - 파이썬/FFmpeg가 새로 설치되면 창을 닫고 `install.bat`을 한 번 더 실행하세요.
3. **`check.bat` 더블클릭** — 환경과 캡컷을 점검하고 `env_report.txt`를 만듭니다. 이 내용을 Claude에게 보내 주세요.

맥: `run_mac.command` (처음 한 번 `chmod +x run_mac.command`, FFmpeg는 `brew install ffmpeg`)

## 3. 사용법

1. **`run.bat` 더블클릭** → 프로그램 창이 열립니다.
2. 원본 영상 선택, 프리셋 선택, 필요하면 강조 단어 입력 (예: `월넛, 도마`)
3. **[1. 분석하기]** — 영상은 아직 바뀌지 않습니다. 처음에는 음성 인식 모델을 내려받아 몇 분 걸립니다.
4. 표에서 확인
   - 회색(✘) = 빼는 문장, 더블클릭으로 넣고 빼기
   - "자막 글자 수정" = 화면 자막만 수정 (오타, 맞춤법)
   - "오프닝으로 지정" = 그 문장을 맨 앞에 미리보기로 붙임
   - 아래에 예상 길이와 오프닝 후보가 나옵니다
5. **[2. 편집 적용]** → 결과 폴더가 열립니다.

결과물 (원본 영상 옆 `StoryCut_결과/영상이름/`):

| 파일 | 용도 |
|---|---|
| `영상_프리셋.mp4` | 자막까지 입힌 완성본 |
| `영상_프리셋_자막없음.mp4` | 캡컷에서 자막을 직접 얹을 때 |
| `영상_프리셋.srt` | 캡컷 자막 가져오기용 |
| `영상_프리셋.ass` | 색 강조 자막 원본 |
| `영상_프리셋_컷목록.csv` | 원본 몇 초를 썼는지 (엑셀) |
| `plan.json` | 편집 계획. 다시 열어 고치고 재적용 가능 |
| `transcript.json` | 음성 인식 결과 (재사용) |
| `캡컷_가져오기_안내.txt` | 캡컷에서 이어서 편집하는 방법 |

명령줄로도 실행할 수 있습니다:

```
python -m storycut.cli presets
python -m storycut.cli analyze 원본.mp4 --preset shorts_story --keywords "월넛,도마"
python -m storycut.cli apply "StoryCut_결과/원본/plan.json"
```

## 4. 프리셋

| 프리셋 | 비율 | 목표 길이 | 컷 속도 | 공구 소리 |
|---|---|---|---|---|
| `shorts_story` 스토리텔링 쇼츠 | 9:16 | 60초 | 빠름 (쉼 0.25초 넘으면 줄임) | 최대 0.6초 |
| `vlog_talk` 작업실 토크 브이로그 | 16:9 | 7~15분 | 느긋함 (0.7초) | 최대 3초 |
| `making_process` 목공 제작 과정 | 9:16 | 30~90초 | 빠름 (0.3초) | 최대 2.5초 |

`storycut/presets/*.yaml` 에서 숫자를 바꾸면 바로 반영됩니다.

## 5. 폴더 구조

```
jbwood-storycut/
├─ install.bat / run.bat / check.bat   더블클릭용
├─ run_mac.command                     맥용
├─ env_check.py                        환경·캡컷 점검 (읽기 전용)
├─ requirements.txt
├─ storycut/
│  ├─ gui.py          화면
│  ├─ cli.py          명령줄
│  ├─ pipeline.py     분석(analyze) / 적용(apply) 두 단계
│  ├─ transcribe.py   Whisper 음성 인식
│  ├─ analyze.py      문장 나누기, 말버릇·더듬기·재발화, 오프닝 후보
│  ├─ timeline.py     계획 → 실제 컷 구간 (단어 경계, 공구 소리)
│  ├─ subtitles.py    SRT / ASS(노란 강조) 자막
│  ├─ keywords.py     강조 단어 (숫자, 목공 용어)
│  ├─ render.py       FFmpeg 렌더링
│  ├─ media.py        FFmpeg 도우미, 무음 감지
│  └─ presets/        프리셋 3종
└─ tests/             자동 테스트 + 테스트 영상 생성기
```

## 6. 개발 단계

- [ ] 2단계: AI 스토리 구성(Claude API) — 도입·상황·갈등·전개·결말, 목표 길이 맞추기, 감정 태그

- [ ] 실제 촬영본 테스트 및 개선

## 알려진 한계

- Whisper는 "어/음"을 받아 적지 않고 생략하는 경우가 있습니다. 이 경우 말버릇은 '공백'으로 처리되어 쉼 줄이기로 정리됩니다.
- 사투리·잡음이 심하면 인식이 틀릴 수 있어요. 표에서 자막 글자를 고치세요(소리는 그대로).
- 말 없이 작업만 한 영상은 1단계에서 처리할 문장이 없습니다(3단계 장면 분석 필요).
